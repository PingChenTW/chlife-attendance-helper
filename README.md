# 一起點名

給同工與年長使用者的大字版點名工具。iPhone、Android 可用，開啟連結即可操作，不要求同工輸入原網站帳密。

**[開啟一起點名](https://pingchentw.github.io/chlife-attendance-helper/)**

**[系統架構圖（互動版）](https://pingchentw.github.io/chlife-attendance-helper/architecture.html)** · [PNG 圖檔](public/architecture.png) · [SVG 向量圖](public/architecture.svg)

首次使用主畫面的人名是空白的，也不放姓名搜尋。

操作：**選本週／上週 → 選小區 → 選聚會 → 加入名單／編輯名單 → 搜尋或顯示全部名單來選人 → 返回主畫面點姓名 → 送出點名**。目前手機名單為空時，按鈕與畫面標題顯示「加入名單」；已有可顯示的人員時改為「編輯名單」，全部移除後回到「加入名單」。各小區、一般與兒童名單分別判斷。

每支手機、每個小區各自保存已加入的人員。同一小區的自選名單沿用於本週、上週與七個聚會。加入或移除只調整這支手機的顯示名單，不會新增、刪除原網站人員，也不會更動出席。重新開啟後會保留名單；清除瀏覽器資料或使用其他瀏覽器，需要重新加入。

選小區後可勾選「只顯示兒童」，依原網站「學齡前、國小」身分篩選（含已受浸與未受浸），聚會項目改成 **兒童主日、兒童排、兒童家聚會**，分別對應原站「主日」、「兒童排(兒童)」、「家聚會(兒童)」。「加入名單／編輯名單」的搜尋及「顯示全部名單」都只列出該小區的兒童。一般名單與兒童名單在每支手機分開保存自選人員，既有一般名單繼續保留；出席寫回各自對應的原網站聚會欄位。兒童主日與一般主日使用同一份原站紀錄，兒童排及兒童家聚會使用兒童專用欄位。兒童篩選由後端執行，分別以 `role=學齡前`、`role=國小` 讀取後合併去重；原站對逗號合併角色會回傳空名單，因此不能合併條件查詢。名單簽章綁定篩選種類；若人員身分或權限已變動，送出前重新核對。若無法確認原站三個欄位，停用兒童選項，避免誤記成人聚會。

支援主日、家聚會出訪、家聚會受訪、排聚會、禱告聚會、生命讀經、福音出訪。正式紀錄以原網站為準。

## 本機練習

需要 Node.js 24 或更新版本。沒有第三方執行套件，不需要 npm install。

```sh
npm run demo
```

開啟 http://127.0.0.1:4173 。所有姓名都是假資料，點名只保存在這次執行的記憶體。

```sh
npm test
npm run build
```

未設定 API_BASE_URL 時，build 產生可獨立運作的靜態練習版，不會連接原網站。

## 正式後端

在自己的後端主機設定下列環境變數。帳密絕不可放入 GitHub、public/ 或 APP_API_BASE_URL。

| 變數 | 用途 |
| --- | --- |
| APP_MODE | live |
| CHLIFE_CHURCH_ID | 原網站召會 ID |
| CHLIFE_ACCOUNT | 原網站帳號，機密設定 |
| CHLIFE_PASSWORD | 原網站密碼，機密設定 |
| ALLOW_WRITES | 預設 false；指定真實測試紀錄驗證後才設 true |
| HOST | 主機對外服務通常用 0.0.0.0 |
| PORT | 由主機平台提供；本機預設 4173 |
| ALLOWED_ORIGINS | GitHub Pages 等前端的完整來源，例如 https://USERNAME.github.io；逗號分隔 |
| SNAPSHOT_SECRET | 建議設定固定、隨機且至少 32 字元的機密簽章金鑰 |
| CHLIFE_DEVICE_TOKEN | 選用，固定的隨機裝置識別碼 |

```sh
node --env-file=.env src/server.mjs
```

也可用附帶 Dockerfile。環境變數在執行時注入，不能放進映像檔。只有一個後端程序／一個實例；工具內的寫入會排隊處理，不能用多個副本取代。登入與更新憑證只存在後端記憶體。

後端亦能直接提供手機介面，這種部署不必使用 GitHub Pages。

## GitHub Pages

1. 將本專案放到 GitHub 儲存庫。
2. Settings → Pages → Source 選 GitHub Actions。
3. 內附 workflow 執行測試、建置與發布。未設定後端時發布的是明確標示的**練習版**。
4. 後端就緒後，在儲存庫 Variables 設定 APP_API_BASE_URL 為後端 HTTPS 網址，再執行 workflow。
5. 後端 ALLOWED_ORIGINS 必須包含該 GitHub Pages 的來源網域。

Pages 只能提供介面，不能代替保存網站帳密的後端。

## 聚會報表與多帳號窗口

手機首頁按「報表」，選本週／上週與大組，可看大組小計、個別小區及可左右捲動的完整表格。CSV 下載可用 Excel 開啟。報表只讀取原網站，不會修改點名；統計完整小區，不受各手機自選名單影響。

- 一般欄位採原網站正式週報的預設「全部」人群與 `split_children_sunday=1`；主日由原站拆分兒童。歷史週次在原站「全部」與明確 `audience=adult` 篩選可能有不同回算結果，本工具跟隨預設週報，不自行另扣人數。兒童主日及兒童排分別讀取學齡前、國小，包含已受浸兒童，與點名頁兒童範圍一致，並註明與週報只計未受浸兒童的「童」欄不同。
- 繁增比例＝主日÷基數；出訪比例＝福音出訪÷基數；家聚會合計＝受訪＋出訪，並非跨項目的不重複人數；家聚會比例＝合計÷基數。小計比率由總人數÷總基數計算。缺值或基數為零時顯示「—」。本週標示進行中。
- 大組、小區依所選來源帳號的完整小區權限動態取得，不固定八個小區；僅有某排權限時不會擴大為整個小區。上游回傳的其他小區、直屬及已結束桶列會排除，小計在本服務重新加總。
- `src/report-config.json` 是基數設定，索引依序為「來源代碼 → ISO 年 → 召會 ID → 小區 ID」。目前 `primary / 2026 / 49` 的八個基數來自使用者圖片（合計 171）。不同來源、召會、新小區與新年度都不以同名套用基數。未設定時仍顯示人數，基數及相關比率為「—」；小計有任一小區缺基數就不顯示小計比率。
- 沒有另設報表資料庫；每次更新重新讀取正式週報。報表 API 與姓名一樣不進入 Service Worker／localStorage。伺服器只暫存登入及原有 30 秒範圍中繼資料。

保留目前點名使用的 `CHLIFE_*` 設定。之後可在 **Render 的機密環境變數** `REPORT_ACCOUNTS_JSON` 加入最多八個額外唯讀報表來源。此欄位是 JSON 陣列，每筆結構如下，以下全為佔位文字：

```json
[{"key":"source-2","label":"第二個服事範圍","churchId":49,"account":"由管理者填入","password":"只填在 Render 機密設定","deviceToken":"每個來源獨立且固定的識別碼"}]
```

`key` 不可重複或使用 `primary`；只用小寫英文、數字及連字號。手機只收到 `key` 與 `label`，不會收到帳號、密碼或憑證。選來源後，後端僅使用該來源的登入狀態與權限。每個帳號失效時不會改用較高權限帳號代查。這些額外來源**只供報表讀取**，不會讓目前點名頁改用另一個帳號寫入；新增點名帳號需另做範圍與儲存流程。新增來源前須確認該範圍適合既有免登入服務，並核對實際權限與正式報表口徑。目前沒有加入額外帳密，尚未驗證未提供的真實帳號或純報表專用帳號；僅有測試替身的來源隔離測試。

報表介面：`GET /api/reports/meta` 傳回本週／上週及非機密來源標籤；`GET /api/reports/weekly?week=2026-W44&source=primary&group=l2:1072` 傳回所選來源、大組下的完整授權小區。`group` 省略時自選第一個授權大組。來源、週次、大組均由後端驗證，不能傳入任意網址或繞過範圍限制。

### 各大組總表（預留，尚未啟用）

第二張參考表的欄位已登記於 `src/report-profiles.json` 的 `all-groups`。`/api/reports/meta` 的 `reportTypes` 可查詢各報表是否就緒；`GET /api/reports/summary?week=...` 已預留，目前明確回覆 HTTP 501 `SUMMARY_NOT_READY`，不以示範數字冒充正式總表，手機主畫面也不增加尚未可用的按鈕。

未來由單一總帳號依實際授權取得各大組資料，列出動態大組、全體小計與上週比較；不直接疊加八個帳號，避免重疊權限造成重複計算。總帳號的登入憑證沿用機密來源登錄窗口，各大組基數另用 level-2 ID 設定，不會套用小區基數。未有總帳號前不宣稱已支援跨大組總表。受浸、新人、青職、青少年、兒童召會生活、福音等新增欄位須確認原網站對應與去重口徑，待確認後在原生報表模組擴充；現有小區週報 API 維持相容。

### 各大組獨立點名入口

專屬連結格式為 `/?group=7`，報表為 `reports.html?group=7`。頁面內切換功能及加入主畫面的啟動網址都會保留大組。各入口的自選名單分開保存，原有不帶參數的第六大組入口與既有儲存鍵繼續保留。尚未設定、格式錯誤或無權限的入口會顯示錯誤，不會自動轉用其他帳號。

在 Render **機密環境變數** `GROUP_LINKS_JSON` 登錄來源與入口；以下帳密是佔位文字，不可將真實值寫進儲存庫：

```json
{"accounts":[{"key":"seventh","churchId":49,"account":"由管理者填入","password":"只填在 Render","deviceToken":"固定且獨立的識別碼"}],"links":[{"group":"7","source":"seventh","groupId":2154,"allowWrites":true}]}
```

`accounts` 與 `links` 各最多八筆；一個來源若確實具備多大組權限，可以由多個入口共用 `source`，不必複製登入帳密。每個入口仍會將原站已授權範圍再限縮至設定的召會與 `groupId`，傳入其他小區代碼不會擴大這個入口的範圍。名單簽章、送出排程與重複送出記錄按入口分開；原有公開入口不會列出新入口的資料來源。未明確設 `allowWrites:true` 時維持唯讀。這些專屬連結延續免登入設計，網址是資料分流，並非使用者身分驗證；知道或推得其他已啟用入口的網址，也能使用該入口。啟用新範圍前需確認可供知道連結的人查看及點名。

全域 `ALLOW_WRITES=false` 會停用所有入口的正式寫入，即使入口設定了 `allowWrites:true` 也不例外。

2026-10-28 第七大組帳號已完成登入檢查：711 區 193 人可點名；611 區 123 人全為唯讀。因此此帳號不能當作八大組共用的點名帳號。第七大組已授權的九個小區由原網站動態取得；個別小區年度基數尚未提供，相關比率顯示「—」。目前未對第七大組進行任何正式出席寫入測試；只有讀取權限與合成資料送出測試。新增入口的實際上線狀態以部署機密設定為準。

## 行為與限制

- 這是依需求設計的免登入工具。知道網址的人可以讀取開放範圍的姓名；正式寫入開啟後也可以點名。CORS、限流與名單簽章都不是使用者身分驗證。
- 後端只提供這兩週，一般名單七項、兒童名單三項；範圍從原帳號的 privileges 取得。沒有新增人員、修改名單、帳號管理或任意網站轉送功能。
- 手機只取得姓名、區排與勾選狀態，不接收原網站帳密或登入憑證。localStorage 只保存自選名單的人員 ID，不保存姓名、出席紀錄或帳密；離線快取只保存介面檔案。
- 點姓名只改畫面，按送出並確認後才寫入。只送出有修改的人，使用明確出席目標，並重新讀取確認。
- 寫入逾時不盲目重送；結果不明會顯示未確認。部分失敗保留仍待送出的選擇；名單改動時提示重新核對。
- 原網站沒有提供給本專案正式承諾的公開 API。介面是依原站前端的實際呼叫建立，原網站改版可能需要調整。
- 工具內部寫入會序列化，但無法對從原網站或其他程式同時進行的修改提供跨系統交易鎖。讀取前後核對只能降低衝突，不能消除所有競態。
- 名單憑證 15 分鐘過期，需要重新讀取；日期切換依台北時區。原網站要求 MFA、驗證碼或強制帳號處理時會停止，不會繞過。
- 手機瀏覽器可能在切到背景或關閉後清除未送出的修改，請點完立即送出。

## 驗證狀態

2026-10-28 已實際確認原網站登入、帳號權限、七項聚會、小區架構，以及 611 區本週和上週名單讀取。已依使用者指定的一筆本週禱告紀錄完成出席寫入，並以獨立查詢回讀確認。未對其他人的紀錄執行變更。實體 iPhone／Android 裝置測試仍待驗證。

程式測試涵蓋冪等送出、逾時回查、部分結果保留、權限範圍、名單變動、CORS、輸入驗證、跨年週次、初始空白名單及每支手機的自選名單保存。行動瀏覽器尺寸預覽不能取代實體裝置驗證。
